# Skill alignment validation, 2026-10-04

Candidate: canonical Skill changes prepared for 0.12.2, based on 0.12.1
(`6a0f4e33`). CLI: `codex-cli 0.159.3`, configured default model; no model
override. These are observed runs, not a claim about every model or future run.

The design follows OpenAI's guidance on concise discriminating descriptions,
conditional instructions, user intent, and real behavior evaluations:
[Skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra),
[Plugin Skills](https://developers.openai.com/plugins/build/skills), and
[Skill evaluations](https://developers.openai.com/blog/eval-skills).

## Observed behavior

| Assessment | Result |
| --- | --- |
| Four focused baseline requests against 0.12.1 | 2/4 |
| Candidate requests with the reviewed grader | 24/24 |
| Complete deliveries with independently inspected previews | 6/6 |
| Official Skill structural validator | All six entrypoints pass |
| Full repository check in a clean source snapshot | 150 tests pass; source, knowledge and Plugin checks pass |
| Gallery preview build | 47 visible previews; 58 immutable IDs, including 11 hidden aliases |

The baseline loaded the drawing workflow for a help-only request and selected
frameworks for a moderation-path request. The candidate avoided those reads and
selected relations. Explicit invocation, implicit discovery, nonprocess branching,
exact/alias/unknown Gallery IDs, missing-data questions, four negative controls,
and help links all met their case-specific checks.

The candidate consists of the 24-case run plus two narrowly scoped fixture/CLI
reruns. Initial false failures exposed evaluation issues: native explicit Skill
injection has no JSONL read event; native image views are omitted from this CLI's
JSONL; `$X$` preserves the literal label X; `--image` consumed a positional prompt
without `--`; and the original style-only repair fixture already exceeded its
width budget. The agent correctly reported that pre-existing width limitation.
The repaired fixture starts with passing machine QA. No failed delivery was
replaced with a simulated success. Original traces and initial reports remain in
the external run directories.

Independent artifact inspection confirmed:

- Collect → Check → Report at 88 mm, with no invented branch.
- X → Y, with W targeting that path's midpoint at 178 mm.
- Context/Mechanism groups with the supplied four labels and no arrows.
- The original three data rows and symmetric measurement errors, correct units,
  an unchanged input TSV, and an 88 mm PDF.
- An in-place black-and-white repair retaining node text, edge endpoints and
  directions; its feedback curve stays below the main path and clear of text.
- Alpha → Beta → Gamma using only the reference's style, without its content.

Labels, arrowheads and group titles were readable; no unintended text collisions
or clipping were observed. Delivery validation and fresh artifact checks passed
for each reviewed result. This maintainer-agent review is separate from the
evaluated agent's self-report and does not certify unexposed image-tool telemetry.

Browser checks verified displayed and copied prompts agree, moderation prompts
ask which path is moderated, and initial `#TFF-0009` loading resolves to
`#TFF-0033` with its card present. No browser console errors were observed.
After adding bilingual support, both UI languages and both clipboard prompts
were checked; English remained selected after reload. Chinese and English
searches locate the same moderation card in either language. All 47 visible
examples have Chinese titles/descriptions; stable IDs and source links agree.
Plugin synchronization now excludes local build artifacts; a real packaging
test verifies source builds remain intact and the generated bundle passes checks.
