# 智能绘图优化方案与验收记录

目标：让 TIKZ-FunFig 在保留科研含义和可编辑 TikZ 输出的前提下，主动
选择能容纳内容的构图，测量真实节点尺寸，避免碰撞，稳定地修复局部问题，
并用有证据的结果复用经验。既有 FigureSpec / Expert 工作流保持兼容。

## 实施范围

| 编号 | 改进 | 可验收结果 |
| --- | --- | --- |
| A1 | 内容与尺寸驱动的模板适合度 | 根据节点数、结构、标签密度和目标宽度筛选，报告排除原因；精确 TFF 查询仍保持精确 |
| A2 | 真实 TeX 测量和空间预算 | 测量节点、标签与分组边界；按行列真实尺寸分配间距；显式文字宽度/最小高度也参与计算 |
| A3 | 可执行布局条件 | 支持对齐、同级等尺寸、阅读顺序、固定位置；布局前识别冲突，布局后验证；语义签名保持关系、方向、组归属与标签 |
| A4 | 按难度选择构图 | 简单图只做必要计算，复杂图比较少量横向/纵向/分组候选；硬条件先过滤，再比较阅读路径和几何质量；空间不足时报告具体冲突 |

| A6 | 普通与 Expert 基础 QA 统一 | 共享文本重叠、PDF 尺寸、最终缩放可读性、检查工具可用性；结构化图增加节点/路径/组/条件检查 |
| A7 | 稳定局部修复与前后验证 | 先处理关联元素，必要时扩大范围；保存候选和上一版，验证语义不变与缺陷改善，劣化方案不覆盖当前源 |
| A8 | 经验证的失败修复经验 | 产品内维护带适用条件的通用处方；结构化记录缺陷、对象、动作、前后指标与构建哈希；不自动公开用户内容或把自评当成功 |
| A9 | 真实变化与失败恢复评测 | 长中文/英文、公式、大节点、菱形、嵌套组、多回路、单栏拥挤、换文字和局部编辑；记录首轮/修复后结果、轮数、时间，独立查看预览 |
| A10 | Skill、知识与本机交付 | 更新六个 Skill 的共享工作流、相关知识/Recipe/Golden，同步便携包，完成检查并安装本机修复版 |

## 实现原则

- 在已有 FigureSpec 与设计记录上增加有限、可执行的条件，不创建第二套
  与 source-of-truth 冲突的图表示。
- 真实测量使用现有 TeX 引擎，无额外 shell escape；缓存按字体、形状、
  标签、宽度和引擎区分，变更后失效。
- 新图由布局规划处理可调整的位置；用户指定的科研坐标/比例和固定区域
  不随审美优化改变。复杂物理示意图的空间含义由任务约束保护。
- 检查顺序：语义与用户硬条件 → 碰撞与最终可读性 → 阅读顺序 → 平衡。
  不使用一个美观总分掩盖硬失败；机器几何检查不替代实际预览审阅。
- 局部修改默认尽量保留当前构图；只有局部空间不够时扩展修改范围。
- 自动优化可交付候选和诊断；视觉 QA 必须在查看最终当前预览后记录。
- 经验来自经过检查的通用案例，用户的图与科研内容保留在其项目中。

## 执行步骤

1. 扩展 schema / runtime：尺寸预算、有限布局条件、折线路径与测量契约。
2. 实现测量、构图候选与局部修复，共享 QA 和模板适合度。
3. 加入失败处方和可追踪修复记录，更新 Skill/知识/Recipes。
4. 添加 Golden、变化/失败恢复测试及可视评测，运行可选布局引擎对照。
5. 同步 Plugin，执行 `./scripts/check.sh`、`git diff --check`、独立查看
   当前图像并验证本机安装包。

ELK 试验使用[官方 layered 算法说明](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

顺序也未优于当前布局。试验中修正了重复端口点导致的箭头方向问题，
所以没有仅凭机器评分把外部引擎升为默认。
